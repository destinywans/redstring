# 权限资源操作与初始化记录管理

- 需求：WAN-105。沿用 `codex/wan-105-role-management-refinement`，依赖已推送、未合并基线 `b10a9bc`。
- 用户明确修正：Permission 只有唯一名称、描述等元数据；查看、变更、审批、删除属于权限与资源的关联。初始化生成的角色与权限也允许编辑和删除。
- 本决定取代此前“权限定义具有单一操作”和“内建定义只读/禁止删除”的设计，保留前一版交付记录作为历史。

## 实现

- 创建权限仅填写名称和描述，不生成任何授权；关联表以权限、目标范围、资源 ID、操作组成唯一记录，支持同一资源多操作。
- 管理关联采用可检索的资源类型树，默认展示折叠类型，搜索展开结果；每个资源展示已关联操作。取消勾选只移除当前所选操作，其他操作和未修改资源保留。无资源分页或跨页选择控件。
- 内建与自定义记录共用编辑、删除入口。删除使用居中确认，同事务清理关系，保留关联另一侧的对象。删除权限递增受影响角色版本，防止旧关联草稿覆盖。
- 保留版本冲突、名称唯一、事务内权限重检和最后有效 RBAC 管理者保护。
- 共用关闭按钮的视觉调整单独在 WAN-96 记录和提交。

## 数据与兼容

- `016_rbac_resource_actions.sql` 将旧权限操作迁移到资源关联，删除权限定义的 action/scope/mode 列。有效权限视图使用关联 INNER JOIN，空权限不生效。
- 旧应用 ACL 冻结为迁移时的应用快照，并继续与个人原 ACL 相交；未来新增应用需明确关联。历史调查、执行、管理动作保留原语义，不进入新操作选择。
- 普通资源支持查看、变更资料和删除可人工维护的资源记录；实际审批针对应用，继续独立于执行。树中区分应用资料与应用访问/审批目标。
- `017_rbac_editable_defaults.sql` 只同步仍存在的基础角色，不因账户更新重建删除项。创建或显式切换已删除基础角色返回明确冲突。旧身份能力需基础角色真实存在并仍有关联；显式 RBAC 授权按实际关联读取。
- 当前页面数据来自既有 PG 记录；没有为本轮填充虚构角色、权限或业务状态。测试使用随机隔离 schema。
