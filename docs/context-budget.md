# 会话上下文、预算与输入清单

源码入口：`internal/inference/context.go`、`internal/httpapi/context_budget.go`、`internal/store/run_context.go`。产品历史以 PostgreSQL 中的消息、分支版本和证据为准；Google ADK 的内存 Session 只属于单次 Attempt。模型切换从下一轮生效，重新使用被冻结的分支上下文，不要求沿用上一个提供商的 Session。

## 一轮请求如何组装

Run 保存模型标识、分支版本、消息和证据快照。Worker 在执行前组装输入；普通重试还可附带同一 Run 的已提交取证记录，并明确标记其历史来源。输入足够小时完整发送，不创建摘要。

超过预算时，组装过程保留：

1. 原始调查目标原文。
2. 最近两个以用户消息开始的完整消息组，不在中间截断问答；最后一组可以是正在等待本轮回答的当前问题。
3. 完整的冻结证据与重试证据前缀。
4. 较早消息的有界摘要，包括约束、已确认事实、假设、排除方向和未解决问题。

每段摘要保留覆盖的原消息 ID，原消息不会被删除或覆盖。历史内容与摘要均标记为不可信来源数据，不能升级为新的执行指令。父子分支、同步和合并依然受原有版本快照规则控制；每次从本轮冻结版本重新准备上下文，不能把其他分支的摘要当作自动共享记忆。

摘要最多分成 8 个块，每块一次模型调用，不带取证工具。自动初查的摘要调用数会从推理预算中扣除，摘要与正式推理还共享截止时间。若一条旧消息、近期完整消息组或证据前缀本身太大，系统明确失败，不会静默删除这些内容以强行发送。

## 模型窗口配置

`OLLAMA`、`OPENAI`、`CLAUDE` 三个提供商前缀分别支持以下环境变量：

```dotenv
OLLAMA_MODEL=<configured-model-name>
OLLAMA_CONTEXT_WINDOW=32768
OLLAMA_INPUT_BUDGET=28672
```

另两个前缀使用相同后缀。`*_MODEL` 可配置逗号分隔的模型名称；当前同一前缀下的模型共用该组窗口设置，应按其中较小的实际能力配置。调整后重启服务。

默认 `context_window=32768`，默认 `input_budget=context_window-4096`。窗口至少为 8192，输入预算至少为 2048，并且不能超过窗口减 4096；剩余空间用于输出。这里的数字是应用配置，服务不会自动从提供商探测真实窗口，需按所用模型能力填写。

预算估算使用序列化内容的 **UTF-8 字节数作为保守单位**：`estimated_tokens` 不是精确 tokenizer 结果，也不是供应商计费用量。中文、多字节字符和长工具定义可能更早触发摘要或拒绝。准备阶段另留 2048 单位基础开销，并为每个工具计入名称、描述及 512 单位余量；提供商适配器在每次请求前再次检查实际序列化请求体，包括新增的工具结果。该保守上界优先避免越界，可能低估模型可利用的实际容量。

## 查看本轮实际输入

有应用查看权限的用户可读取：

```text
GET /api/v1/runs/{run_id}/context
```

返回最近一个成功准备并保存的 Attempt 输入清单。数据库按 Attempt 保存，不用新版本覆盖旧 Attempt；当前 HTTP 入口只返回该 Run 的最新一份，不提供全部 Attempt 的分页历史。

主要字段：

| 字段 | 含义 |
| --- | --- |
| `run_id`、`attempt_id`、`model_id` | 本次执行及模型身份 |
| `context_revision` | 冻结的分支上下文版本 |
| `input_budget`、`estimated_tokens`、`estimation` | 预算、保守估算及估算方法 |
| `summary`、`summary_calls` | 实際生成的摘要与消耗的调用数 |
| `summary_source_ids` | 摘要覆盖的原消息 ID |
| `recent_message_ids` | 保留原文的消息 ID；未压缩时包含完整历史消息 ID |
| `evidence_ids` | 输入中冻结及重试证据的 ID |
| `messages` | 提交给本次正式推理的组装消息 |
| `created_at` | 清单生成时间 |

清单在正式推理之前、持久化租约有效时写入。若准备上下文或摘要失败，该 Attempt 不会产生成功清单；接口可能返回较早 Attempt 的清单，或在尚无清单时返回不存在。应结合 `attempt_id` 和 Run 状态判断，不将旧清单当作失败 Attempt 已经发送过的输入。后续工具调用产生的动态输入仍由 Run 证据和事件保存，初始清单不会不断改写为整段内部执行轨迹。

## 失败与能力边界

模型预算未知、工具占用过大、单条历史消息过大、固定证据／近期轮次装不下、摘要为空或失败、摘要调用数超限，以及最终摘要仍超预算，都会返回明确错误并保留原历史。可选择更大且正确配置的模型窗口，或由人明确派生一个范围更小的调查；服务不会伪装成“上下文无损”后悄悄丢弃内容。

切换模型可携带已提交文本、证据与可追溯摘要，不迁移提供商隐藏推理、opaque cache 或内部调用栈。摘要仍是模型生成内容，有遗漏风险；源 ID 便于人核对，不构成逐事实正确性的保证。

这里处理的是一次调查的输入管理。跨调查经验和 Runbook 的原文、审核发布、作用域检索及导出，见 [知识治理契约](knowledge-governance-contract.md)。当前不会把每轮对话自动变成长期事实，也没有把所有历史记录自动注入每个模型请求。
