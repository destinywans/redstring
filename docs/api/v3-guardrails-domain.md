# V3 Guardrails 领域接线边界

`PATCH /api/v1/guardrails/{id}` 只确认当前授权环境的策略状态、修订区间和审计已在同一事务持久化。强制策略不能关闭。当前 V3 主程序没有登记策略的生产来源，也没有实际 Agent 执行器消费策略；响应的 `runtime_status: unconnected` 不表示已执行拦截。

可信执行器接线顺序：

1. 从经审核的固定目录调用 `RegisterGuardPolicy` 登记明确环境的策略，不能从普通请求或 Mock 直接注册。
2. 执行器用 `StartRun` 建立持久运行。在策略评估前调用 `GuardDecisionHooks.PolicySnapshotForRun(runID, policyID)`；它从运行记录取得环境，返回快照交接时间、当前修订和启用状态。关闭状态不得执行该策略；快照时间不是稍后实际阻断或脱敏的时间。
3. 对启用状态评估决策。对允许继续或因关闭而跳过的结果，在对外放行前调用 `ValidateGuardDecision`，重新核对运行、环境、修订和启用状态。发生阻断或脱敏时，立即以快照修订调用 `ReportGuardDecision`，且不得填入 `ObservedAt`；它在持久事务中取得决策上报时间，重新核对运行、环境及修订启用区间，再原子保存脱敏事件与审计。两种最终校验的提交都是该次决策的授权移交点；之后的 PATCH 不追溯取消已移交的在途决策。校验失败或修订变更时不得对外宣告该结果，执行器须重新评估或失败关闭。需要晚到上报的可信生产者另用 `RecordGuardEvent` 携带真实采集的决策时间。两种上报路径都不得把原始输入、工具参数或脱敏前后的内容写进事件。
4. 由 WAN-117 公共组装层将可信执行器接到该接口，并验证真实运行路径。领域包仅提供钩子，当前没有生产调用者。

`GET /guardrails` 的七个 UTC 日桶、计数和每策略计数仅统计当前可见、拥有上报时间和策略修订证明的**已上报事件**，与 200 条事件展示上限无关。列表可包含七日窗口外的历史事件；标签计数不能当成列表总数。旧事件缺少决策证明，仅在事件列表标记为 `recorded_only`；没有上报记录只能证明零条已上报，不能证明零次实际触发。响应固定标记 `aggregation_basis: reported_events`、`coverage: unknown` 和 `partial: true`。原始来源、脱敏片段、结论无持久生产者，详情中为 `null`。冻结前端仍假设这些字段完整且使用静态图表日期，需另行适配；本领域实现不是页面验收。

公共接真实执行器前，还需修正 `CompleteRun` 取得运行行锁后才生成 `finished_at` 的时钟顺序，避免等待上报时把完成时间记到事件时间之前；该运行模块不属于本批独占文件。
