# V3 悬浮卡：持久对象与未知值（WAN-121）

`GET /services/{id}/peek` 和 `GET /people/{name}/peek` 属于只读发现领域。两者先按当前环境和对象权限解析持久记录，缺失与无权统一为 404；在当前可见范围内，应用 ID/key 对应多个环境、ID 与另一应用 key 冲突，或同名人员对应多个账号时返回 409，不任取一条。服务路径接受搜索和 @mention 使用的环境复合 ID、真实告警组携带的应用 ID，以及设计稿链接使用的应用 key。未配置发现存储或策略时返回 503。

| 字段 | 当前来源和语义 |
| --- | --- |
| 服务 `id/name/env` | 有效应用、环境绑定；响应 `id` 是应用与环境复合 ID。 |
| 服务 `tier/team/owner` | 等级来自环境档案（仅可表示 T0–T2），团队来自登记归属，`owner` 是登记档案的 `owner_label`，属于配置文字，并不证明某人当前负责。缺失为 `null`。 |
| 服务 `status/kpis/oncall/change` | 本领域尚未接入经过应用、环境、授权、来源完整性和新鲜度检查的观测与发布来源。依次返回 `null`、`[]`、`null`、`null`；登记档案中的 `oncall_user_id` 不能证明当前班次。 |
| 人员 `id/name/role` | 当前可见的有效真人账号；`role` 取自用户可维护的 `job_title` 资料，缺失为 `null`，不是 RBAC 职能角色。 |
| 人员 `oncall/load` | 尚无可供他人查看的当前值班披露规则及完整工作负载来源，均返回 `null`。分配给此人的部分事件数量不能冒充总负载。 |

当前实现没有接入额外实时观测源，因此不能把空 KPI 或 `null` 解读为健康、无告警、未值班或零负载。后续如接入来源，应先沿用服务详情已定义的应用/环境归属、来源身份、时效、完整覆盖和事件权限检查，并在返回前复核当前授权。

## 冻结前端契约差异，待 WAN-117 适配

- `web/src/v3/api/types.ts` 中 `ServicePeek.tier/team/status/owner/oncall/change` 均要求非空，且 `env` 只接受 `prod/staging/test`；真实登记可能缺资料或使用其他环境。本接口上述未知字段允许 `null`，环境保留真实 key。
- `PersonPeek.role/load` 当前要求非空，`oncall` 只声明可省略；本接口三个字段均显式允许 `null`，其中 `role` 是资料标题。
- 当前服务卡会把非 `warn/danger` 状态显示为“正常”，人员卡把空值班显示为“非值班”。直接切换到真实响应会产生错误陈述；在前端适配未知态前，不能据此宣称悬浮卡已通过页面验收。
- 当前服务卡“发起调查”按钮仍链接固定演示调查 ID；本后端接口不提供这个调查目标。

机器契约在 `scripts/v3-openapi-search.py` 中生成。此文档记录字段来源与冻结消费者差异；公共路由状态及前端接线由 WAN-117 维护。
