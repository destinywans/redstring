# 已知问题（v0.1.0）

v0.1.0 是 beta，不建议用于生产环境。这里列出发布时已经知道、还没修或按设计暂不提供的问题，按模块分组，每条写现象、影响、绕行办法和登记号。登记号指向两份缺陷登记：[生产验收登记](releases/2026-10-09-production-acceptance.md)（PA-01～PA-104）和 [缺陷收敛登记](releases/2026-10-16-defect-convergence.md)（PA-105 起）。

- 级别：P2 指功能受限、有绕行；P3 指显示或文字问题；“缺能力”指后端有接口、界面没有入口，或产品还没有这项能力；“设计限制”指按已定方案暂不提供。
- 遇到这里没有的问题，请按 README 的[「反馈」](../README.md#反馈)提 issue；安全问题按 [SECURITY.md](../SECURITY.md) 私密报告。
- 本文按 2026-10-19 发布验收轮（第 3 轮）收工后的登记写，已扣除发布前修好的 PA-232、PA-245～PA-253、PA-255、PA-259、PA-263、PA-264、PA-266；PA-257 修好了把提案时修订说成“当前”的问题，下面只列还没做的过时提示。

## 告警级别（severity）支持的取值

告警的 `severity` 标签（不区分大小写，去掉首尾空格）按下表归到 P1～P4：

| 产品级别 | 认得的原始取值 |
| --- | --- |
| P1 | `p0`、`p1`、`critical`、`fatal`、`emergency` |
| P2 | `p2`、`high`、`error`、`warning`、`warn` |
| P3 | `p3`、`medium`、`info`、`notice` |
| P4 | `p4`、`p5`、`low`、`none`、`debug` |

- 没有 `severity` 标签，或取值不在表内（如 `major`、`minor`、`page`、`ticket`、`alert`）的告警，各页显示“级别未知”，悬停说明是“未填写”还是“无法归类”。不会让页面失败，也不会被猜成某一级。
- 级别未知的告警照样可以新建事件（在抽屉里由人选级别），也可以写复盘；按 P1～P4 过滤时不会命中它们。
- `major`、`minor`、`page`、`ticket` 在不同工具里含义不一，所以故意不映射。建议在 Alertmanager / Prometheus 规则里用表内的取值。

## 范围与环境限制

不是缺陷，但使用前要知道（详见 README 的[「还没做」](../README.md#还没做)和[「安全须知」](../README.md#安全须知)）：

- 没有做性能与 24 小时稳定性测试；只在一个实验集群、三个服务、单机单进程上验证过；模型只验过 DeepSeek。
- 没有独立安全审查；登录不校验二次验证（TOTP 只能在账号安全里登记）；OIDC 单点登录有实现，没有验收；备份恢复、升级迁移、自身监控告警没有验收。
- 在线演示和 `make web-dev` 是示例数据模式，页面数据是示意，不连后端。
- 用 Docker Compose 运行整个应用（`--profile app`）目前不可用：`api` 服务不传实例配置，模型也没设 `OLLAMA_API`，会以旧版模式启动、页面停在加载骨架。请用宿主机方式（见 README 的快速开始）。
- 2026-10-16～10-17 之后没有重跑独立演练套件，发布后补跑，结果更新在 [v0.1.0 发布说明](releases/v0.1.0.md) 里。
