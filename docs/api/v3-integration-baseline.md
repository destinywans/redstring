## DTO 与路由

- 页面字段和枚举以 `web/src/v3/api/types.ts` 为准，方法、路径、参数与语义以 `docs/api/v3-contract.md` 为准。当前授权不修改前端；字段无法由可信来源填满时，返回明确的不可用/未接入错误，保留该主契约行 `mock`。不得补虚构的零、空数组、健康状态、费用或模型能力。
- 通用 JSON 错误为 `{ "error": { "code": "...", "message": "..." } }`；`204` 无正文。面向用户的单一文案按 `Accept-Language: zh-CN | en-US` 返回，标识符和查询语句不翻译。分页接口遵守 `{ items, total, page, page_size }`；从可见全集计算的计数不得由截断样本推断。
- 业务模块只实现和测试自己拥有的领域文件。集成会话独占 `cmd/aiops/v3.go`、`internal/httpapi/`、`internal/rbac/`、两个 OpenAPI 生成脚本、生成契约、V3 主契约和路由矩阵、`PLAN.md`、`CHECKPOINT.md`。业务模块提交可注册自身路由，但公共接线、权限门禁、主契约状态及生成文件由集成会话逐切片处理。已有旧路径只有完成 V3 语义替换后才能开放。
- 路由注册后还须通过实际处理、V3 授权、DTO 映射、OpenAPI、受影响检查，才可把主契约从 `mock` 改为 `implemented`；外部系统实连和前端 HTTP 模式验收单独记录。辅助接口不计入 166 项。

## 实例、环境与授权

- `AIOPS_V3_INSTANCE_CONFIG` 显式启用 V3。生产实例仅 `prod`，独立域名、数据库和凭据；非生产实例不能包含 `prod`。客户端不能选择实例边界。已绑定 V3 的库漏配该配置时拒绝旧模式启动。
- 浏览器请求用单值 `X-AIOps-Environment`。非生产普通请求必须给出已知环境；生产可省略而取 `prod`。非生产 `all` 只聚合当前用户有权读取的环境，并禁止平台或外部写入，写请求返回 `409 env_view_only`；唯一现有结构化只读 POST 例外是 `/knowledge/search`。SSE、审计导出下载和上传内容下载这类无请求头的读取，必须从持久记录确定环境并按当前会话与授权复核。异步任务也须复核，不沿用旧 cookie 中的权限快照。
- V3 授权使用 `rbac.V3Policy` 的当前持久化授权：先查环境 `view`，再查稳定 module/action 代码及目标范围。对象路由先从持久目标确定应用或团队，再逐对象检查；仅路由级 module 授权不足以覆盖应用/团队范围。操作枚举为 `view/change/delete/approve/execute/manage`。写事务在同一连接上锁定目标、复核授权、写业务状态与审计；不要借用另一连接绕开锁或产生单连接池死锁。
- 旧角色等级和旧 ACL 不得充当 V3 权限。`approve` 当前在策略层拒绝，直到一次有效的二次验证挑战能绑定精确提案；任何模型只能只读取证，对外部系统写入须先生成提案，经人工批准再交独立执行器。未迁移旧路由在 V3 实例返回 `501 v3_not_implemented`。

## 错误与审计

- 会话缺失或失效用 `401 unauthorized`；已知环境但无授权用 `403 forbidden`；未知/缺失环境或无效输入用 `422` 的稳定代码；`all` 写入用 `409 env_view_only`；来源、授权存储或必需 DTO 不可用用明确 `503`；未接适配可用 `501`。已存在但未接线的能力不得以成功空值、旧实现结果或路由存在冒充可用。避免把隐藏对象的细节泄露给无权用户。
- 所有平台写请求和 Agent 工具调用写 `management_audit`；业务变更与成功审计须在同一事务提交，审计失败回滚业务写入。审计包含稳定 action、actor、target、outcome，以及可证明的 `environment`/`environment_id` 和有依据的 `application_id`，以便 V3 审计读取判定范围。失败/拒绝若需保留证据，按独立事务记录真实结果，不能把失败写成成功。
- 审计只保存必要的资源 ID、动作、范围、结果和安全元数据；不得写凭据、Vault 引用、原始日志/查询、对话证据、令牌或敏感响应。工具读取记录开始及结果，且读取前后重新校验会话、目标与权限。`management_audit` 的历史链只证明迁移后的连续性；037 在现有大表的回填锁时尚未验证。
