## 亮点

Redstring 是可自托管的 AI 运维工作区：让 AI 分头调查，由人来批准。

- **分支调查**：每个怀疑派生成一条分支，从父分支的某个上下文版本继承，之后独立取证；排除的分支留下理由，确认的结论经合并预览写回主线，过期的预览不能覆盖更新的版本。
- **证据有出处**：取证工具只读，结论带引用，能追到背后的工具调用、检索结果和 Trace；模型的猜测不算证据。
- **批准与执行分开**：写操作先生成一份冻结的提案，由两位非发起人用通行密钥批准，再交给与 Agent 隔离的执行器；结果不明时先核对实际状态，不盲目重试；恢复后持续观察再判定。
- **从告警到复盘的闭环**：告警 → 认领 → 调查（画布或对话）→ 静默或回滚提案 → 两人批准 → 执行与验证 → 事件结案 → 复盘 → Runbook。复盘的审阅与发布在界面上还没有入口，要用接口（PA-128）。
- **交付**：GitLab 变更与 Kubernetes 修订对应、AI 建议回滚、告警规则经配置仓库启停、跨环境配置提升（Runbook、告警规则、Agent、画布模板），都走人工审批。
- **集成中心**：Kubernetes、Prometheus、Loki、Alertmanager、GitLab、Elasticsearch、Tempo 等连接器；日常只读查询不需要 AI。
- **平台**：成员、角色权限矩阵、生产与非生产实例隔离；模型支持 Ollama、OpenAI 兼容接口（如 DeepSeek）和 Claude；界面支持中英文和深浅色，使用系统字体，不下载字体文件。
- **不知道就说不知道**：数据源没接、没权限或取不到时，页面写明原因，不把未知显示成 0、空列表或“正常”；已知例外见[已知问题](../KNOWN_ISSUES.md)。

## 已知问题

见 [docs/KNOWN_ISSUES.md](../KNOWN_ISSUES.md)，按模块列出现象、影响和绕行办法，其中包括告警 `severity` 支持的取值。主要几条：

- 告警 `severity` 只认表内的取值；其余显示“级别未知”，仍可以新建事件（由人选级别）和写复盘，按 P1～P4 过滤时不会命中。
- 新建抑制规则、通知路由需要先接入经审查的 GitOps 仓库（PA-123、PA-141）。
- 复盘没有详情页，审阅与发布只能用接口（PA-128）；记忆、评测案例、Agent 新版本等几项管理操作只有接口、没有界面入口。
- AI 对话取证的指标与日志固定取最近 15 分钟（PA-196）。

## 不适用的场景

- **生产环境**：没有做性能与 24 小时稳定性测试，没有独立安全审查，登录不校验二次验证（TOTP 只能在账号安全里登记），OIDC 单点登录有实现但没有验收；备份恢复、升级迁移、自身监控告警没有验收。
- **接入生产系统**：默认配置不启用任何写入；凡是配置了写凭据的模块都可能写外部系统，包括执行器（Kubernetes 回滚、Alertmanager 静默、告警规则启停、配置提升）、交付模块（触发、取消、重试 GitLab 作业，提交 Argo Workflows，GitOps 或 SSH 发布）和 MCP 工具（是否只读取决于管理员登记的白名单和凭据）。只给测试环境的凭据，详见 README 的[「安全须知」](../../README.md#安全须知)。
- **对公网开放**：默认开发配置不是 HTTPS、`AIOPS_SECURE_COOKIES` 未开启；见 README 的[「安全须知」](../../README.md#安全须知)。
- **规模与部署形态**：只验过一个实验集群、三个服务、单机单进程；多副本、大数据量、其他版本的 GitLab/Prometheus 没有验证；用 Docker Compose 运行整个应用目前不可用（`api` 服务不传实例配置，模型也没设 `OLLAMA_API`），请用宿主机方式。
- **范围外的能力**：多租户、长会话自动摘要、完整 CI/CD；向量库只实现了 PostgreSQL + pgvector；模型只验过 DeepSeek。

## 升级与迁移

这是第一个公开版本，没有更早的发布版本，也就没有升级迁移要做。数据库结构由服务启动时执行内置迁移（`migrations/`）建好。用仓库里更早的提交建过库的，新版本启动时会执行增量迁移；验收实例一直这样升级，但“升级迁移”没有作为一个场景单独验收，有重要数据时先备份。
