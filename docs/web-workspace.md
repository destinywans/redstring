# Web 工作区 · 2026-09-20

本轮实现浏览器工作区与必要的后端对接，沿用 Linear 中八张正式概念图，第三张使用修正版。目标是尽量还原布局与卡片交互；示意文字、模型名称和指标数值不自动成为真实产品状态。此段描述首次 Web 实现的历史范围。用户随后再次要求暂停全部验证：当前禁止测试、构建、校验、浏览器检查、迁移与重启。最新基础设施/观测/告警/平台设置入口及边界见 [SRE 观测工作区](observability-workspace.md)。

## 运行入口

先运行 `make init db`、`pnpm --dir web install --frozen-lockfile`。两个终端分别运行 `make web-api` 与 `make web-dev`，访问 `http://127.0.0.1:5173`。前者读取 `.env` 后将 API 地址固定为 `127.0.0.1:18080`，允许的 Origin 固定为 `http://127.0.0.1:5173`；Vite 已使用该 API 目标，不需要放宽 CORS 或 CSRF 检查。

构建托管方式：`make web-build`，然后 `AIOPS_WEB_DIR="$PWD/web/dist" make run`。Go 服务提供静态文件和 SPA 历史路由；`/api`、`/healthz`、`/openapi.json` 保持独立。缺失资源返回 404，HTML 不缓存，构建资源可长期缓存。Web 目录只能指向构建产物，不能指向仓库根目录或凭据目录。

## 八个设计场景

| 概念图 | Web 入口与行为 |
| --- | --- |
| 01 应用概览 | `/applications/detail`：应用、调查入口、已有资料和只读查询（`/` 现为跨应用关注工作台）；真实模式按接口可用数据展示，不编造指标 |
| 02 调查画布与节点对话 | `/investigations/:id`：节点、连线、拖拽缩放、选中节点对话与侧栏对话 |
| 03 证据对照与卡片收纳（修正版） | 调查页 `?view=evidence`：证据来源、配置／日志对照，以及卡片展开、折叠、最小化、隐藏和恢复 |
| 04 上下文分支合并 | 调查页 `?view=merge`：审查来源、目标、证据和冲突，选择消息或仅引用证据后明确确认 |
| 05 回滚审批 | `/actions?inv=<调查ID>`：读取版本，创建提案，查看准确摘要与模板；批准、拒绝、撤销和执行分别操作 |
| 06 执行与恢复观测 | `/recovery?plan=<提案ID>`：从既有执行恢复视图，展示实际状态与结果，符合条件后关闭调查并保存报告 |
| 07 Runbook 与经验 | `/knowledge`：导入、检索、原文、索引状态、经验草稿及确认 |
| 08 模型与集成设置 | `/integrations`：模型、连接器和 Embedding；账号/团队/审计保持独立，治理总览在 `/platform/settings`，`/settings` 保留自动化策略 |

`/investigations` 可选择或创建调查。上述场景共享壳层、当前应用、主题与权限；调查卡片收纳不改变业务对象。窄视口允许页面滚动与布局调整，不通过缩小全部字体强行容纳桌面布局。

## 数据与上下文边界

PG 中的消息、证据、版本和持久事件是权威历史。每次推理 Attempt 使用独立 ADK Session，从冻结上下文构造输入；切换模型不会改写已提交历史。子分支继承指定父版本后独立演进，父变化需显式同步，合并创建目标新版本；过期预览不能直接覆盖新版本。

节点内和侧栏对话针对同一个选中分支。布局、选中项和草稿按用户保存，不能通过拖拽或隐藏取消推理。SSE 正式事件带序号，重连续读后重新取得后端已提交快照；流式片段不能冒充已提交答案。布局写入失败应保留当前编辑并提示失败，不能宣称已经持久化。

## 预览与真实模式

入口 `/?preview=1` 提供带显式标记的设计预览。预览数据独立于真实 API：图表、调查、提案与恢复状态均为示例；不调用真实模型、不提交批准或执行、不导入实际知识。离开预览后需要正常登录。

真实模式只展示已有后端数据。设置中的 `configured_unverified` 表示适配器已配置，未证明连接健康。无连接、空结果、读取失败均不等于健康。当前恢复结果只包含验证汇总，没有逐点时序，因此真实恢复页展示请求增量、采样数、时长与原始结果；只有预览页使用示意趋势图。

## 新增的三条对接接口

| 接口 | 作用与边界 |
| --- | --- |
| `GET /api/v1/integrations` | 返回安全配置清单与 `configuration_mode: server_managed`；无服务 URL、凭据和凭据文件路径，不提供虚假的“保存成功” |
| `GET /api/v1/applications/{id}/deployment` | 仅返回登记 Deployment 的镜像、副本和历史版本摘要，不接受任意 namespace／对象，不返回环境变量 |
| `GET /api/v1/action-plans/{id}/execution` | 读取已有执行，页面刷新后继续观测；无执行返回 404，绝不因此入队新动作 |

三条接口最低权限都是 viewer。管理员、操作员、只读用户的写权限仍由服务端检查。完整字段见 [API 契约](api-contract.md) 和 [OpenAPI](../internal/apicontract/openapi.json)，共 47 项操作。

## 审批与恢复

审批弹窗绑定打开时审查的提案 ID、目标和摘要；后台轮询不改换批准对象。另一位操作者改变决策时刷新状态，409 冲突要求重新审查。批准后仍需明确执行，执行提交失败可以重试同一不可变计划，由后端复用既有执行。

首版仅允许登记 Deployment 的历史 Pod 模板／镜像回滚。验证要求批准目标已收敛、探针健康且有真实请求，默认观察 **180 秒**，不沿用概念图中的五分钟示意。未知写结果先核对实际对象，不盲目重复回滚。当前演示指标适配器限单副本，不能推断为通用多副本生产恢复方案。

关闭调查须引用同调查最新成功执行，且没有活跃推理或执行。报告保存后刷新调查详情及列表缓存，避免画布继续显示可编辑的旧状态。确认后的经验才进入知识检索；索引失败保留原文并允许重建。
