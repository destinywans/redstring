## 决策与参考

保持快速交付可用于博客和简历的 SRE 作品这一初衷：平台提供日常查看与调查入口，Prometheus/Loki/现有 Kubernetes 和告警系统继续提供数据，不自建采集器、时序存储、日志索引或全套告警规则引擎。AI 是分析与调查能力，用户查询数据、筛选、查看详情不需要启动模型。

参考作者博客项目 `src/components/ops/` 中的 `navigation.ts`、`Observability.tsx`、`Infrastructure.tsx`、`Incidents.tsx`、`Workspace.tsx`。这些页面的数据来自浏览器本地演示状态；只借鉴分类、列表、详情和上下文衔接，示例 Trace、固定资源数量、模拟通知送达与规则开关不迁入真实产品。

### 当前能力映射

| 入口 | 当前实现 | 明确边界 |
| --- | --- | --- |
| `/observability/metrics` | 登记查询、应用环境、快捷或自定义时间、真实序列图及原始采样值、手动刷新 | 只查询服务端已登记 PromQL，不是完整 Prometheus/Grafana 编辑器；不自动采集或轮询 |
| `/observability/logs` | 应用环境限定的 Loki 日志、文本和级别筛选、单条选择 | 筛选只作用于已返回数据；文本推断级别会标注；不开放任意 LogQL |
| `/observability/traces`、`/observability/topology` | 分类入口及缺少数据源说明 | 尚无 Trace/服务调用图适配器，不能把静态登记或日志伪装成真实拓扑 |
| `/infrastructure` | 已授权应用的登记环境/绑定总览，真实 Deployment 副本、镜像、版本与采集时间 | 非全局集群 inventory；集群、节点、Pod、事件、主机、网络、存储、中间件类别保留待接入说明 |
| `/alerts`、`/incidents` | 外部告警和事件两种视图，共享事实记录、筛选、详情、认领、创建或继续调查、同环境观测跳转 | 告警恢复不等于调查结案；列表最多最近 200 条，统计仅覆盖已加载范围；不给出全局健康结论 |
| `/alerts/sources` | 管理员读取已登记告警来源、映射与通知渠道 | 配置不代表连通；没有启停告警规则、外部静默或立即发送的假操作 |
| `/platform/settings`、`/platform/roles` | 单工作区治理入口与实际三角色权限说明 | 成员/团队/审计保留独立页面；工作区基本资料只读，无假保存 |
| `/settings` | 原自动化策略入口保持可用 | 仍沿用原有版本控制、默认关闭与预算，不因增加菜单自动启用 |

云服务/内部平台能否接入取决于实际协议、鉴权与数据关联。当前实现只声称已有 Prometheus、Loki、登记 Kubernetes、Alertmanager 接收与飞书 outbox 代码路径；不声称所有云厂商日志、Trace 或 IAM 已受支持。

## 从观测到调查

1. 用户直接查询已授权应用环境的指标或日志，看到来源、实际时间窗口、空值、采样上限等信息。
2. 可固定整个返回结果、某条指标序列或某条日志，选择同应用同环境的既有调查分支，或新建调查根分支。
3. 固定内容包含原始结果、来源、时间及 selection 元数据；单项选择明确标记为部分结果，所有快照均不代表完整遥测数据集。
4. 固定后准备问题草稿，由用户在调查中决定是否发送给 AI；没有自动模型调用。现有草稿保留，历史证据不冒充最新实时状态。
5. 应用、环境、查询或时间变化时，旧响应不能变成新范围结果，旧快照不能误绑定新范围。失败保留上次结果并明确提示。

日志从指定窗口选择最新 N 条，再按时间升序展示；达到返回上限不表示覆盖全部日志。AI 取证独立限制为最多 10 条（服务端上限更小时从小），页面浏览保留配置上限；有限样本不能证明应用全面健康。Lima 主机页复用登记的 `vm_*` 查询，展示采集状态、CPU、内存、磁盘、网络及 systemd 状态，不代表已实现主机资产发现。

证据大小沿用后端 256 KiB 上限。新建/固定接口尚无客户端幂等键；网络结果不明确时界面停止盲目重试并提示核对。已确认新建的调查在本页会话保留；刷新后通过调查列表继续，不能宣称强幂等保证。

## API 补充（OpenAPI 0.5.0）

- `GET /applications/{id}/telemetry` 始终登记，返回 `{metric_query_ids,logs_configured,configured,limits}`。没有全局遥测配置时为空能力且 `limits:null`；有配置时 limits 取适配器归一化后的实际窗口、历史范围、步长、每序列样本及日志数量上限。无效环境、应用权限失败仍是错误，不能静默变成无数据。
- `POST /applications/{id}/metrics` 与 `/logs` 为只读查询，最低角色改为 viewer，并要求应用 view 权限。仅这两个明确 POST 路由是只读例外；同源校验、服务端绑定、时间和结果上限保持。创建调查、固定证据仍要求 operator 和应用 operate。
- `GET /operations/catalog` 管理员专用，返回 `{sources:[{id,type,state,mappings}],channels:[{id,type,state,scope}]}`。来源仅映射标签和应用环境，渠道仅 ID/type/scope；不输出 token、Webhook 地址、凭据内容或文件路径。`state` 为 `configured_unverified`。
- `GET /incidents/{id}/events` 要求应用 view；未分配应用的异常仅管理员可读。返回 `{kind:"alert_receipts",items:[{id,status,received_at}],limit:100,truncated}`。读取现有 `ops_alert_occurrences`，按接收时间和 ID 倒序；这是去重后的告警接收记录，不是完整审计或有效状态变迁。晚到 firing 记录不改变当前已恢复状态。

本轮不新增数据库结构；前轮 009/010 迁移仍未执行。新页面要在用户允许构建及必要迁移后才能更新现有预览。
