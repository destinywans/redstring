# 资源目录与资源关系 · WAN-101 · 2026-09-21

用户已批准按 [平台设计图](../design/platform-2026-09-21/) 实现资源目录、资源关系：右侧详情固定覆盖基础页面，不挤压列表或关系图；示例数据先写入 PostgreSQL，再经后端读取，后续接真实来源。CI/CD 继续暂停。本轮产品状态为 **In Review，待用户体验确认**。

## 已实现范围

- 资源目录支持检索、类型/应用/来源/负责人/团队筛选、排序和分页；详情包含概览、关联应用、相关资源与变更记录。
- 资源关系提供节点与关系展示、根节点和深度等筛选、节点详情；图形位置属于前端展示，当前不持久化。
- 新增资源、应用环境关联、关系和变更记录存储，以及列表、详情、关系图和管理员手工登记 API。手工登记只创建元数据，不创建基础设施，也不表示已采集健康状态。
- 全部读取遵循登录会话、应用 ACL 和全局环境范围；共享资源的应用关联裁剪到可访问范围，关系两端均须可见。完整语义见 [Resources API](../resources-api.md)。

## 数据与规模边界

迁移 `migrations/011_resources.sql` 已在本机 review PostgreSQL 执行。显式运行 `scripts/seed-resource-demo.py` 导入 **50 个资源、28 条关系，关联 7 个现有应用**；现有应用资料未修改。启动过程不自动播种。

这些记录真实存储在 PG、经后端接口读取，但内容仍是界面验收示例：`is_mock=true`、`source_kind=mock`、`source_id=ui-review-2026-09-21`。状态、指标、趋势、事件和日志不能用作真实业务或基础设施健康证据。播种仅维护自己的来源记录与关联，不覆盖已有应用资料和连接器绑定；非示例来源的 ID 冲突会拒绝写入。

当前模块先加载最多 10,000 个授权资源、20,000 条关系，再执行有界过滤和遍历；超出显式失败。列表每页 1–100 条；关系图深度 1–3，最多输出 300 个节点、600 条边，并返回截断标记。这是当前小规模验收实现，扩大规模前需将列表过滤、计数、分面和图遍历进一步下推到索引化数据库查询。
