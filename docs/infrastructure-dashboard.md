# 基础设施 Dashboard

[WAN-112](https://linear.app/wansss/issue/WAN-112) 的 V2 图表方案于 2026-09-22 获用户批准实施，同时修复资源采集失联和相关指标缺失。需求讨论与备选历史保存在 Linear；此文记录代码版本对应的接口和统计口径。

## 页面与交互

资源总览使用资源数量卡、类型横向柱状图、工作负载类型环形图、CPU/内存趋势、节点时间热力图、集群运行摘要、异常卡和采集状态。总览不提供混合资源表、分页或局部环境筛选；完整目录仍由分类页承担。节点/主机专题使用实际指标的容量仪表和 CPU×内存散点，点击进入覆盖式资源详情。

沿用平台字体、字重、主题、全局环境和资源权限。图表带单位与时间，缺失数据断线或显示缺数，不补 0；采集正常不等于业务健康。图表交互不发起业务动作。

## 聚合接口

`GET /api/v1/resources/overview?environment_scope=all`，可使用资源接口既有的来源、应用等筛选条件，无分页参数。

服务端复用资源可见范围，先执行 RBAC 与全局环境约束，再生成统计；不返回其他用户无权访问的资源、全源计数或连接凭据。未知环境返回空范围。前端不再为总览逐页下载全目录。

响应包含：

- `stats`、`distribution`、`workload_types`：当前可见资源及运行实例的独立计数。
- `clusters`：可见节点就绪情况、工作负载与副本摘要、资源源同步情况。
- `nodes`：去重的计算资源、当前指标、容量与 15 分钟序列；超过上限以 `nodes_truncated` 明示。
- `compute_groups`：节点、主机分别在散点样本截断前聚合；未知容量不推算总容量，指标加权只使用有效样本和真实分母。容器上限可能来自共享宿主，不代表独占物理容量。
- `metrics`：采集覆盖计数及有真实容量依据的节点加权 CPU/内存序列。
- `sources`：可见范围内的源状态、最近成功采集与指标覆盖。
- `anomalies`：当前采样可确认的运行异常；超出上限以 `anomalies_truncated` 明示。
- `generated_at`、`window_seconds`：聚合时间与趋势窗口。完整机器契约见 `scripts/resources-openapi.py` 及生成的 OpenAPI。

## 统计边界

Pod 为运行实例，Event 为运行记录，不混入长期目录总量。已从完整成功快照中消失的对象不算当前资源，但数据库历史保留；采集失败不会推断为删除。

资源运行状态、资源发现同步、性能指标状态分别判断。失联或过期资源不根据最后一次值直接计为当前运行异常；只有可确认的当前状态进入异常摘要。不同资源类型有不同就绪语义，不能把 Service 的 Observed 当成失败。Deployment 所属 ReplicaSet 不重复累计目标副本。

同一 Kubernetes Node 与其明确映射的 Lima 主机只保留一份计算指标身份。独立主机保留；主机容量不再叠加到节点容量上。CPU/内存加权仅使用具备实际容量与有效样本的节点，不能把缺数节点作为零负载。

历史统一到 30 秒桶、15 分钟窗口；缺项用 null。瞬时指标需独立满足鲜度条件，未来时间异常不能当作有效采样。CPU 部分失败不应抹去有效内存，反之亦然。真实节点与容器化 kind 节点的指标作用域必须明确，不能以共享 Docker 宿主机的用量冒充每个 kind 节点的独占用量。
