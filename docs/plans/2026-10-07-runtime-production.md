## 需求及完成标准

- WAN-240：正式人类来源录入→确切来源版本/hash/摘录生成事实候选→人工确认、冲突登记、裁决及来源撤回。事实身份、作用域与审计可追溯；重复请求不重复产生对象；源撤权、下架、版本漂移时读写失败关闭。人工发布资料与候选事实不冒充 AI 自动发现或外部来源自动审核。

验收采用正式注册 HTTP 路由、独占临时 PostgreSQL 随机 schema 及受控本地模型/工具协议。需要核对正常链、权限隔离、版本冲突、撤权、取消/失败、幂等与审计回滚，不以编译成功替代执行证据。真实付费模型、生产数据、外部基础设施写入、前端、性能/24h不在本次验证范围。

## 实现选择与理由

这是助手对已授权需求的实现细化：

1. 新实例必须有正常登记入口，不能依赖测试 SQL、历史数据或关闭的 legacy 路由；因此补充记忆来源、Agent 与版本、案例的必要创建接口。
2. Eval 和 Agent 共用不可变版本执行配置，包括精确模型 ID、Prompt 版本及摘要、工具白名单和预算。改变配置必须创建新版本，避免评测与发布对象漂移。
3. 首批 Eval 执行明确限制为无工具版本的 Prompt 比较；拒绝带工具配置，不让单例文本检查假装验证了工具行为。实际 Agent 仍可使用已获准的四类只读取证工具；写动作继续经过明确提案、人工批准和独立执行器。
4. 记忆从明确人类发布的资料精确摘录，再做人工确认与冲突治理。自主 AI 提炼、语义冲突判定和向量召回不是本轮完成标准。
5. 已有发布和等级管理继续使用当前会话、角色/范围、乐观修订和审计；新增运行入口把这些配置落实到执行。环境上限由真人平台管理员管理，应用管理员不能自行提高环境上限。
